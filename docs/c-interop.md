# C interoperability

Flux can emit a C header for the current stable C export ABI. The versioning and platform-boundary rules are defined in `docs/native-abi.md`:

```sh
flux emit-c-header path/to/package -o flux_api.h
```

The header declares `FLUX_C_ABI_VERSION` (currently `2` for project/package compilation) so native consumers can pin the export contract they were compiled against. It contains declarations for `pub fn` exports, typedefs for public transparent aliases of supported ABI types, typed macros for public compile-time scalar constants, layouts for public `Copy` structs and enums used across the boundary, and plain C function-pointer typedefs for ABI-safe `Copy` callback signatures. Private functions/constants and `main` are not exposed. Current supported ABI types are `i64`, `bool`, `str`, `error`, recursively copyable public structs whose fields are themselves supported ABI values, recursively copyable public enums whose payloads are supported ABI values, and function values whose parameters plus zero-or-one result are themselves ABI-safe `Copy` values. Multiple return values lower to a generated C result struct whose fields are named `v0`, `v1`, and so on; fields and function signatures preserve a directly named public alias through generated `flux__alias_<Name>` typedefs. Chained public aliases preserve their declared alias relationship in the header, and alias dependencies are emitted before aliases that refer to them even when Flux source uses forward alias declarations.

`i64` lowers to `int64_t`, `bool` to C `bool`, and function `str` / `error` values lower to borrowed `const char *`. C callers must not free or retain those borrowed function-result pointers beyond the lifetime guaranteed by the Flux value that produced them. Public compile-time `str` constants instead expand to ordinary escaped C string literals with static storage duration.

Generated constants use compiler-prefixed names such as `flux__const_DEFAULT_LIMIT`. ABI v2 callable exports use deterministic package/module-qualified linker names of the form `flux__abi_<module-hex>__fn_<Name>`; `<module-hex>` is the lowercase hexadecimal encoding of the stable module identity documented by the package loader. For example, two packages that both export `parse` no longer publish the same linker symbol. Public struct and enum tags use the corresponding `flux__abi_<module-hex>__type_<Name>` form, preventing package headers with the same source-level value-type name from colliding. Public enum discriminant typedefs and constants are module-qualified as `flux__abi_<module-hex>__tag_<Name>` and `flux__abi_<module-hex>__tag_<Name>_<Variant>`. Generated C keeps its shorter internal source-level identifiers and binds callable exports to qualified linker symbols with compiler-owned assembler labels, while the generated header declares the qualified identifiers directly. Multi-return header struct tags use the same module qualification. The generated header is C++ compatible through an `extern "C"` block. Compiler regression coverage compiles generated headers as C11 and compiles package C output to an object before inspecting exported linker symbols, so source-level or module-identity changes cannot quietly desynchronize the foreign ABI.

Public `Copy` structs cross the boundary by value with their field order and compiler-owned C field names fixed by the generated header. Public `Copy` enums also cross by value: the discriminant is fixed to signed 32-bit storage, variants have deterministic zero-based tag constants, and payload variants use a compiler-owned C union/struct layout emitted in dependency order. Because these exported aggregates contain only recursively `Copy` ABI values, they do not create hidden ownership transfer, drop, or aliasing obligations for C callers. ABI-safe function values cross as plain C function pointers, so a C caller may pass a compatible native function into an exported Flux function and Flux may invoke it directly with no callback registry, serialization layer, or trampoline object. Callback signatures containing lists, nested callbacks, interfaces, or other ownership-sensitive values remain rejected until those values have explicit foreign ownership/lifetime contracts. Importing arbitrary C functions by symbol from Flux, library/link metadata, owned foreign values, and broader cross-FFI ownership rules remain part of the interoperability work.
