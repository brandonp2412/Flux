# C interoperability

Flux can emit a C header for the current stable C export ABI. This package export boundary is Flux's stable C FFI surface today: native C code can call exported Flux functions and pass ABI-safe `Copy` callbacks directly into Flux. Flux can also import the current narrow ABI-safe C-symbol subset on Linux and Android; ownership-sensitive foreign values remain separate unfinished interoperability work rather than being implied by the stable export contract. The versioning and platform-boundary rules are defined in `docs/native-abi.md`:

```sh
flux emit-c-header path/to/package -o flux_api.h
```

The header declares `FLUX_C_ABI_VERSION` (currently `2` for project/package compilation) so native consumers can pin the export contract they were compiled against. It contains declarations for `pub fn` exports, typedefs for public transparent aliases of supported ABI types, typed macros for public compile-time scalar constants, layouts for public `Copy` structs and enums used across the boundary, primitive `Copy` optional wrappers, and plain C function-pointer typedefs for ABI-safe `Copy` callback signatures. Private functions/constants and `main` are not exposed. Current supported ABI types are `i64`, `bool`, `str`, `error`, primitive `i64?` / `bool?` / `str?` / `error?`, recursively copyable public structs whose fields are themselves supported ABI values, recursively copyable public enums whose payloads are supported ABI values, and function values whose parameters plus zero-or-one result are themselves ABI-safe `Copy` values, including recursively nested function values. Nested callback typedefs are emitted dependency-first so an outer function-pointer typedef can safely name its inner callback parameter/result type. Multiple return values lower to a generated C result struct whose fields are named `v0`, `v1`, and so on; fields and function signatures preserve a directly named public alias through generated `flux__alias_<Name>` typedefs. Chained public aliases preserve their declared alias relationship in the header, and alias dependencies are emitted before aliases that refer to them even when Flux source uses forward alias declarations.

`i64` lowers to `int64_t`, `bool` to C `bool`, and function `str` / `error` values lower to borrowed `const char *`. C callers must not free or retain those borrowed function-result pointers beyond the lifetime guaranteed by the Flux value that produced them. Public compile-time `str` constants instead expand to ordinary escaped C string literals with static storage duration.

Generated constants use compiler-prefixed names such as `flux__const_DEFAULT_LIMIT`. ABI v2 callable exports use deterministic package/module-qualified linker names of the form `flux__abi_<module-hex>__fn_<Name>`; `<module-hex>` is the lowercase hexadecimal encoding of the stable module identity documented by the package loader. For example, two packages that both export `parse` no longer publish the same linker symbol. Public struct and enum tags use the corresponding `flux__abi_<module-hex>__type_<Name>` form, preventing package headers with the same source-level value-type name from colliding. Public enum discriminant typedefs and constants are module-qualified as `flux__abi_<module-hex>__tag_<Name>` and `flux__abi_<module-hex>__tag_<Name>_<Variant>`. Generated C keeps its shorter internal source-level identifiers and binds callable exports to qualified linker symbols with compiler-owned assembler labels, while the generated header declares the qualified identifiers directly. Multi-return header struct tags use the same module qualification. The generated header is C++ compatible through an `extern "C"` block. Compiler regression coverage compiles generated package headers through both C11 and C++17 consumers and compiles package C output to an object before inspecting exported linker symbols, so source-level or module-identity changes cannot quietly desynchronize the foreign ABI.

Primitive `Copy` optionals cross by value as `struct flux__optional_<type> { bool has_value; T value; }`, exactly matching generated Flux C layout. They therefore add no hidden allocation, ownership transfer, drop, or aliasing obligation. Optional recursively ABI-safe public structs/enums use dependency-ordered wrappers with collision-safe package/module-qualified public identities, so they may appear in public fields, aliases, exported parameters/results, and ABI-safe callback signatures without inventing heap ownership.

Public `Copy` structs cross the boundary by value with their field order and compiler-owned C field names fixed by the generated header. Public `Copy` enums also cross by value: the discriminant is fixed to signed 32-bit storage, variants have deterministic zero-based tag constants, and payload variants use a compiler-owned C union/struct layout emitted in dependency order. Because these exported aggregates contain only recursively `Copy` ABI values, they do not create hidden ownership transfer, drop, or aliasing obligations for C callers. ABI-safe function values cross as plain C function pointers, so a C caller may pass a compatible native function into an exported Flux function and Flux may invoke it directly with no callback registry, serialization layer, or trampoline object. This applies recursively to callback parameters/results that are themselves ABI-safe function values because they remain `Copy` native function pointers rather than closure environments. Callback signatures containing lists, interfaces, or other ownership-sensitive values remain rejected until those values have explicit foreign ownership/lifetime contracts.

Linux and Android packages can also import an existing C symbol directly without application-authored C/JNI glue:

```flux
extern c "sqlite3_libversion_number" fn sqliteVersionNumber() -> i64
```

The quoted name is the exact linker symbol and the Flux function name is the typed source-level alias. Safe imports deliberately accept only `i64`, `bool`, borrowed `str`, and borrowed `error` parameters, and only `i64`, `bool`, or `void` results. A native API whose result is a borrowed C string pointer may be declared through Flux's deliberately narrow unsafe escape hatch:

```flux
unsafe extern c "getenv" fn nativeEnv(name: str) -> str
```

`unsafe extern c` additionally permits only borrowed `str` or `error` results. The declaration is an explicit trust boundary: Flux cannot prove how long the native pointer remains valid, so the native API/caller must guarantee that lifetime for every Flux use of the returned value. Using `unsafe` for an otherwise safe scalar/void import is rejected as unnecessary, and `unsafe` still does not admit aggregates, lists, optionals, interfaces, callbacks, or any other ABI shape whose layout/ownership contract is undefined. Imported functions may be called directly but cannot escape as first-class function values or implement Flux interfaces without an ordinary Flux wrapper. On Android this is the advanced NDK/native-library escape hatch only: ordinary Android framework access continues to use compiler-owned `android.*` bindings and generated JNI/JVM glue, so application code does not need Java/Kotlin/JNI bridge files, method channels, serialization buses, or a plugin registry.

Package `[native].libraries` and `[native].search_paths` supply validated linker inputs to Linux native builds and Android NDK builds. Search paths remain package-relative manifest data and library names remain logical `-l` names; Flux does not accept arbitrary linker command fragments through the manifest. Android resolves those inputs with the selected ABI's NDK Clang toolchain. A static third-party library may therefore be linked directly into `libflux.so`; dynamic dependencies are not automatically copied into APK/AAB outputs yet and must not be assumed bundled. All-ABI AAB builds require each configured native library to be linkable for every ABI being built (NDK/system libraries satisfy this naturally). Owned foreign values, richer imported signatures, automatic redistribution of dependent shared objects, and the broader safe cross-FFI ownership model remain separate Milestone 19 work.
