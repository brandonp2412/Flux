# Flux Roadmap

Flux aims to provide the practical application-development reach of Flutter while remaining a native, ahead-of-time compiled, function-first language. The language is built around functions, immutable data, explicit state, interfaces/capabilities, strict static typing, and composition. It does not use classes, inheritance, widget subclasses, mixins, controller hierarchies, or exception-based recoverable errors.

## Non-negotiable language/product principles

- [x] Python-like readability with low ceremony.
- [x] Function bodies use `{}`.
- [x] Control-flow blocks use indentation.
- [x] Strict static typing.
- [x] No comments in Flux source; `#...` outside strings is a syntax error rather than a comment form.
- [x] No lint/warning tier for source cleanliness: violations such as unused named bindings/parameters/loop or pattern variables are compile errors. A leading `_` explicitly marks an intentionally ignored binding.
- [x] No ternary/conditional-expression syntax; value selection uses control flow or value-producing `match` rather than `a if condition else b`/`?:` forms.
- [x] Namespace, enum, interface, and platform qualification uses dot syntax (`Outcome.Ok(...)`, `Storage.load(...)`, `android.vibrate(...)`).
- [x] No source-language generics.
- [x] No `try` / `catch` / exceptions for recoverable failures.
- [x] Explicit multi-value returns and `error` values form the recoverable-error model.
- [x] Functions, data, and interfaces are the primary abstraction model.
- [x] No classes or inheritance in Flux.
- [x] No mixins or class-oriented extension hierarchy.
- [x] No widget/controller/view-model object hierarchies in UI code.
- [x] Immutable values by default; local mutation is explicit and locally visible through typed `var` bindings and assignment; ordinary `let` bindings, parameters, destructured bindings, and loop variables remain immutable.
- [x] **Beautiful by default is a non-negotiable product goal:** ordinary Flux UI written by a developer with little or no design expertise renders through compiler-owned semantic typography, spacing, sizing, color, interaction, accessibility, and presentation-state defaults without requiring a hand-built design system; explicit application styling remains the straightforward higher-priority escape hatch.
- [ ] Rust-class memory-safety goals without requiring Rust-level annotation density in normal application code.
- [ ] Rust-class native performance is a non-negotiable release-build target: generated programs should remain in the C/C++/Rust performance class without a mandatory VM, garbage collector, interpreter, or framework runtime tax.
- [ ] Zero-cost abstractions by default: high-level language/library/UI constructs must compile away when their semantics require no runtime work, and redundant bounds/safety/dynamic-dispatch checks should be eliminated when statically proven unnecessary.
- [x] Native AOT output for application and server/headless targets: current Linux application and headless `fn main` builds compile through optimized native Clang output with no VM/interpreter, while Android applications produce ABI-specific native shared libraries packaged into APK/AAB artifacts. Future backend replacement remains tracked under the typed-IR/native-backend milestone rather than reopening the AOT product contract.
- [x] Portable source lowers to real platform implementations rather than a browser/VM/widget-emulation wrapper on the current application targets: the same flat Flux UI lowers to native GTK4/Wayland controls on Linux and native Android Views, while target-specific APIs remain explicit and unreachable target-only code tree-shakes without poisoning portable builds. Future targets must preserve this native-platform contract rather than reopening the product principle.
- [x] **No user-written platform bridges:** Flux source calls current Android platform capabilities and native UI/lifecycle callbacks directly; the compiler/toolchain owns the required JNI/JVM/DEX/native entry glue, with regression coverage proving direct callbacks and no method-channel, serialization-bus, plugin-registry, or application-authored Java/Kotlin/JNI requirement. Future platform bindings must preserve this source-level contract.
- [x] **Native-first platform lowering:** current Linux UI lowers directly to GTK4/native Wayland integration, Android uses direct NDK APIs where available (including API-level/lifecycle entry points) and compiler-generated direct JNI/framework calls only where Android requires JVM APIs, and unreachable helpers are tree-shaken. Future backends remain required to use the thinnest optimizable native boundary rather than a mandatory framework runtime.
- [x] The LSP, debugger, profiler, formatter, test runner, package tooling, and hot reload are first-class parts of the language product: all are exposed through the user-facing `flux` workflow, reuse compiler-native source/diagnostic/build semantics rather than separate framework layers, and have checked-in regression coverage. Production-depth follow-ups remain tracked in their dedicated milestones without reopening this product-integration principle.

API ergonomics rules: the ordinary/default operation gets the shortest obvious spelling; extra words qualify genuinely non-default variants rather than the common case. For example, ordinary text-file reading is `file.read`, not `fs.readText`. One-shot operations that naturally produce a result must not expose callback-shaped application APIs merely to work around runtime ownership or scheduling; use ordinary return values for synchronous work and `async`/`await` for asynchronous work. Compiler/runtime callbacks may remain internal implementation details, and inherently event-driven APIs such as UI event handlers may still accept functions.

- [x] Efficient bootstrap interface/dynamic dispatch for runtime polymorphism: interface values are closed-world tagged by-value unions and `Interface.capability(interfaceValue, ...)` lowers to a tag switch calling the mapped free function, with no heap allocation, vtable, reflection, or object identity. - [x] Optional positional/named parameters with explicit compile-time primitive defaults, including top-level constant references and call-site default expansion.

## Null/optional-value ergonomics

Flux currently reserves `nil` specifically for `error`; a general optional-value design must therefore be explicit and must not weaken type safety.

- [ ] Optional value types, likely `T?`, with non-optional types remaining the default.
  - [x] Bootstrap explicit Copy optionals: `i64?`, `bool?`, `str?`, `error?`, recursively Copy struct/enum values, closed interface values, and first-class function values through aliases such as `Mapper?` are distinct static types; `none` is separate from error-only `nil`; ordinary inner values inject at typed optional bindings/assignments/calls/returns; aggregate/interface/function optionals lower by value through allocation-free tagged structs in dependency-safe native type order; non-Copy list/resource-shaped optionals remain rejected until owned transfer/borrow semantics exist; formatter/IR/semantic traversal preserve the syntax; remaining optional-aware operators stay tracked below.
- [x] Null/optional-aware access analogous to Dart `?.`: optional Copy-struct receivers support safe field access with single receiver evaluation, absence propagation, chained access, and flattened optional field results; non-optional receivers and untyped bare `none` are rejected. Struct literal/update fields now also lower ordinary Copy values into optional fields through the same explicit tagged representation instead of relying on invalid implicit C conversion. Non-Copy optional receivers remain sequenced behind owned-value transfer/borrow semantics.
- [ ] Optional-aware indexing analogous to Dart `?[]`. Blocked on ownership-safe optional non-Copy collection values: bootstrap optionals intentionally reject list/resource-shaped payloads, so optional list receivers do not yet exist to index without weakening Milestone 4 guarantees.
- [x] Coalescing analogous to Dart `??`: the optional left operand is evaluated exactly once, present values bypass the fallback, absent values lazily evaluate a type-compatible fallback, optional fallback chains preserve optionality, formatter/IR tooling preserve the operator, and native lowering remains allocation-free.
- [x] Coalescing assignment analogous to Dart `??=` where mutation is valid: mutable optional locals accept `value ??= fallback`, preserve the canonical ergonomic spelling through formatting, reuse the allocation-free optional/coalescing lowering, evaluate the fallback lazily only when the current value is absent, and retain ordinary static assignment/mutability checks.
- [x] Safe optional unwrapping via binding patterns: `if let value = optionalValue:` and `elif let ...` evaluate a Copy optional exactly once, enter the branch only when present, infer and bind the concrete inner type only in that branch, support `_` ignores, reject bare `none`, non-optional values, and binding shadowing, preserve formatter/semantic/CFG/typed-IR branch facts (including interface capability reachability after unwrapping), and lower directly through the optional tag without assertions or allocation. Direct presence-check flow promotion is completed separately below.
- [x] Avoid routine runtime null assertions; bootstrap Flux intentionally has no postfix force-unwrap/null-assertion syntax. Attempting `value!` produces a targeted diagnostic that directs developers to safe `if let` unwrapping or lazy `??` fallback instead, so ordinary optional handling cannot silently introduce a runtime null assertion.
- [x] Flow-sensitive promotion after optional/type checks: stable immutable Copy-optionals checked directly with `value != none` / `none != value` promote to their concrete inner type only in the proven-present branch, while `value == none` / `none == value` promote in the corresponding `else` branch. Promotion is branch-local, lowers through an allocation-free snapshot/tag test plus native value shadow, and intentionally does not promote mutable `var` bindings whose value may change after the check.

## Async/generator ergonomics

Adapt the convenience of Dart's async language features while preserving Flux's explicit error-return model. The intended source model is native `async fn` plus `await`: an async function keeps its ordinary declared return shape, calling it creates compiler-owned task state, and `await` yields those declared values directly. Flux should not require a source-level `Future<T>`/`Promise<T>` generic or user-visible completion callback to express ordinary asynchronous work. The bootstrap compiler lowers reachable `async fn` declarations to compiler-owned native task structs with copied arguments, detached pthread-backed execution, declared result storage, and deterministic task-state release; zero-, single-, and multi-value return shapes including explicit `error` remain ordinary Flux values. Straight-line top-level awaits whose live state is entirely `Copy` now lower to compiler-owned resume states and child-completion continuations: the parent worker returns instead of blocking, the child resumes the parent after completion, and root/blocking consumers wait on a task condition rather than joining a child thread. Direct `return await ...` forwarding and direct awaits inside one arm of a simple boolean `if` now use the same non-blocking continuation path, including mutable outer `Copy` state saved across suspension and fallthrough after the branch. Multiple sequential direct awaits within that selected arm also split into continuation states, preserving branch-local and outer `Copy` values across each suspension; native regressions build/run taken, skipped, and multi-await branch paths end to end. Awaits in loops, matches, complex branch conditions/promotion scopes, awaits distributed across both branches, and other not-yet-split expression shapes retain the safe blocking fallback. General CFG-wide suspension/resumption for those remaining placements is still required before the unchecked suspension item below is complete.

- [ ] `await` suspension syntax that yields the awaited function's ordinary declared return values and is valid only in an async context.
- [x] Async failures returned explicitly through normal Flux `error` values/multi-value returns, not thrown as exceptions or hidden in rejected promises.
- [ ] Streams/sequences as explicit types/capabilities.
- [ ] Generator functions.
- [ ] `yield` / `yield from` equivalent if it fits ownership rules.
- [ ] Cancellation as an explicit capability/value.

# Milestone 4 — Ownership and memory safety

The ownership track now has an explicit compiler-level copyability classification rather than relying on ad-hoc list checks. Bootstrap scalar handles (`i64`, `bool`, `str`, `error`), function values, closed interface values, and recursively copyable structs/enums are `Copy`; `void` is not a value and local list/view types are deliberately non-copy until owned collection storage and move/borrow rules exist. Existing mutable-binding and aggregate-storage safety gates query that classification, so future non-copy value types inherit the conservative restrictions automatically. Direct non-copy moves are represented on the semantic CFG and a deterministic forward may-analysis computes moved-value state at every reachable CFG node; use-after-move diagnostics consume those normalized path facts rather than maintaining a second syntax-shaped branch/loop ownership state machine. Borrowed list-parameter aliases are likewise reclassified from normalized reaching-definition/value provenance before move-state propagation, including transitive aliases, so the bootstrap borrow checker no longer carries a parallel syntax-tree reborrow analysis. Zero-copy local list views now also participate in CFG-liveness ownership validation: a list owner cannot move while a derived slice/indexed-list/`first`/`last`/`single`/`take`/`skip`/`chunked` view or a list-typed binding projected by list destructuring/matching remains live, while a move after the view's final use stays valid. Expression-scoped list-match bindings retain their normalized borrow-source value, and nested-list aggregates preserve embedded borrow provenance through ordinary items, spreads, reachable conditional collection branches, and list comprehensions whose elements remain borrowed views, so wrapper IR cannot hide a live zero-copy view and permit its owner to move early.

- [x] Define copyable primitive/value types with alias-aware structural classification shared by semantic validation.
- [ ] Move semantics for non-copy values.
  - [x] Bootstrap direct local transfers (`let destination: T = source`) move non-copy values, preserve ordinary reuse for `Copy` types, and conservatively merge moves across `if`/exhaustive `match` branches.
  - [x] Bootstrap loop control-flow recognizes iteration-safe direct moves through CFG back-edges: fallthrough and `continue` paths expose the moved source on a later iteration and fail, while paths that leave the loop through `break`/`return` do not create a repeated read.
  - [x] Return-terminated ownership paths do not poison reachable sibling/post-loop state because move facts propagate only over actual CFG successors; zero-iteration loop exits likewise preserve the pre-loop state where appropriate.
  - [x] Nested direct-move loop analysis follows composed CFG edges across `if`/`match`, nested loops, branch-specific `break`, and `continue`, removing the former syntax-shaped loop-exit ownership bookkeeping.
  - [x] Bootstrap direct-local move path-state is computed to a fixed point on the semantic CFG with deterministic move origins and reachability facts; compile-time primitive conditions and statically empty integer ranges remove impossible CFG edges before ownership propagation so dead moves do not poison live owners.
  - [x] Follow-up: fresh local definitions kill stale same-name move facts before CFG propagation to successors, so a non-copy value created and moved inside a loop is fresh on the next iteration, and reusing a branch-local binding name after its scope does not inherit the older value's moved state. Reads in the defining node still observe the incoming state before the new definition exists, preserving use-after-move checks while separating successive definition identities operationally.
  - [ ] General move analysis across calls, aggregate fields, partial moves, and owned resource types after normalized control-flow ownership facts exist. The current bootstrap has no consuming non-copy call boundary to analyze yet: list parameters are immutable borrows, structs/enums reject non-copy fields, and owned resource types have not landed. Do not invent consuming-call syntax merely to advance this checkbox; extend the normalized move facts when the first owned non-copy parameter/aggregate/resource contract exists.
- [ ] Immutable borrows.
  - [x] Bootstrap local list/view reads, indexing/slicing, transforms, iteration, matching, and list function parameters are non-consuming immutable borrows of their local owner; borrowed list parameters can be rebound through direct local alias chains without incorrectly moving either the parameter or an earlier borrowed alias.
  - [x] Reachable non-copy name reads are represented explicitly as immutable-borrow facts on normalized CFG ownership nodes, derived from typed IR value reachability rather than syntax-wide read collection. Use-after-move validation consumes those borrow facts, so compile-time-dead nested regions such as a short-circuited boolean RHS do not spuriously borrow a moved owner while runtime-reachable borrows still fail deterministically.
  - [ ] First-class borrow/reference types and inferred borrow lifetimes for owned values.
- [ ] Exclusive mutable borrows.
- [ ] Lifetime inference.
- [ ] Prevent use-after-move.
  - [x] Reject later reads of a non-copy local after a direct bootstrap move, including conservative post-branch invalidation for paths that can rejoin later code.
  - [x] Direct-local use-after-move diagnostics are driven by CFG/IR move-state before each normalized evaluation node, including loops, branch joins, `break`, `continue`, and returns.
  - [ ] Extend CFG/IR-wide move-state analysis to consuming calls, partial moves, future owned aggregates, and owned resource types.
- [ ] Prevent dangling borrows.
  - [x] Bootstrap live-view move exclusion for zero-copy list borrows: CFG liveness rejects moving a local list owner while a derived slice, nested-list index/property (`first`/`last`/`single`), `take`, `skip`, `chunked`, list-rest pattern, list-match rest, destructured nested-list element, transitive view binding, or local nested-list literal containing its descriptor remains live, while permitting the move immediately after the borrow's last reachable use. Dedicated regression coverage now pins both sides of the `chunked` lifetime boundary: moving the owner while chunk descriptors remain live fails, while moving it immediately after their last reachable use succeeds. Full first-class lifetime inference and escaping-borrow validation remain pending.
  - [x] Follow-up: value-producing enum/list `match` results preserve zero-copy list-view provenance through the selected arm, including nested list views reached through expression-scoped arm bindings, so a live match-selected view prevents moving its owner while a move after the view's last use remains valid.
  - [x] Follow-up: preserve embedded nested-list borrow provenance through list spreads and conditional collection elements; the borrow analysis traverses the dedicated IR wrappers, ignores statically unreachable collection branches, keeps an embedded inner-list owner borrowed while the constructed aggregate remains live, and releases that restriction after the aggregate's final reachable use.
  - [x] Follow-up: nested-list comprehensions preserve borrow provenance from scoped element bindings into the constructed aggregate; moving the source owner is rejected while a comprehension-projected inner view remains live and becomes valid immediately after the aggregate's last reachable use.
  - [x] Follow-up: descriptor-preserving nested-list `filter`/`where`, `concat`, and nested-result `flatten` keep embedded list owners borrowed until the transformed aggregate's last reachable use; capture-free anonymous functions also reject list returns so stack-backed collection storage cannot escape a callback before owned collection transfer/lifetime semantics exist.
  - [x] Follow-up: live-view move validation resolves each live alias through the definitions that actually reach the move node, and transitive borrow provenance follows resolved definition identities rather than globally matching a binding name. Mutually exclusive sibling branches may therefore reuse local view names without an unrelated borrowed definition falsely poisoning a valid owner move, while real same-path transitive views remain protected.
  - [x] Follow-up: nested-list `for value in source` bindings retain their normalized borrow source from the foreach iterable. Moving the outer list owner while a projected list element is still live now fails with the same CFG-liveness borrow diagnostic as destructuring/match views, while a breaking path may move the owner after the element's final reachable use.
  - [x] Follow-up: list-typed foreach, destructuring, and match-pattern bindings that are already proven borrowed views now propagate that borrowed-definition identity through direct local aliases. Rebinding such a view is an immutable reborrow rather than a move of the view binding, while the alias still keeps the original list owner live and blocks moving that owner until the alias's final reachable use.
- [ ] Prevent aliasing violations.
  - [x] Bootstrap non-copy aliasing is immutable-only: local list/view storage cannot be declared mutable, borrowed list parameters and derived views may only form immutable reborrow aliases, and assignment cannot upgrade those aliases into mutable access. Regression coverage pins both mutable-declaration and assignment rejection, so the current bootstrap cannot create simultaneous mutable/shared aliases before first-class exclusive borrows exist.
- [ ] Deterministic destruction/resource release.
- [ ] Safe closures/captures under the ownership model.
- [ ] Thread-safety/sendability rules.
- [x] Narrow, explicit `unsafe` escape hatch only where necessary: the bootstrap language reserves `unsafe` for native FFI declarations, where `unsafe extern c` is accepted only for borrowed `str`/`error` results whose foreign pointer lifetime Flux cannot prove. Safe scalar/void imports reject unnecessary `unsafe`, and undefined aggregate/owned/function/interface ABI shapes remain rejected rather than being admitted by the escape hatch.
- [x] First bootstrap borrow checker over normalized semantics/IR rather than parser syntax: direct non-copy moves, immutable non-copy reads, borrowed list-parameter reborrows, path-sensitive move state, zero-copy list/view borrow provenance, and use-after-move diagnostics are derived from CFG/typed-value/reaching-definition facts. Borrow-source provenance is now queried directly through `ControlFlowGraph` rather than being reconstructed inside the type checker, keeping this ownership fact on the normalized IR boundary. Full borrow/reference types, inferred lifetimes, mutable aliasing, dangling-borrow prevention, partial moves, and drop semantics remain tracked explicitly above rather than being implied complete.

# Milestone 6 — Concurrency

- [x] Compiler-owned native task model for the current `async fn` / direct-`await` bootstrap: each reachable async invocation lowers to private task state containing copied arguments, native pthread execution, declared single/multi-value result storage, and deterministic join/free at `await`, with no source-level task/future generic or callback-shaped application API. Task boundaries currently admit only compiler-classified `Copy` parameters/results so borrowed lists and other non-copy values cannot cross threads before sendability/owned-transfer rules exist; unreachable async functions tree-shake without pthread support. Structured concurrency, cancellation propagation, task-integrated timers/event loops, and higher-throughput scheduling remain tracked separately below rather than being implied complete.
- [ ] Structured concurrency. Bootstrap worker scopes now expose `worker.joinChildren() -> error`, which recursively drains every currently registered descendant of the calling worker (or every root worker and its descendants when called from the main thread) using compiler-owned parentage and ordinary native joins. Each worker thread is joined before its child registry is drained, so descendants spawned immediately before a parent exits remain attached long enough to be joined; retryable internal joined-state tracking preserves cleanup if a descendant join reports an error. The API returns explicit join failures and tree-shakes with the worker runtime when unreachable. Cancellation already propagates through descendants; automatic lexical scope draining, task/async integration, failure aggregation, and ownership/sendability enforcement remain required before this item is complete.
- [x] Cooperative worker cancellation propagation: `worker.cancel(handle) -> error` marks the target worker plus every currently registered descendant it spawned, and `worker.cancelled() -> bool` lets worker code observe the request without unsafe native thread termination. Worker parentage is compiler/runtime-owned through thread-local execution identity, children started after their parent is already cancelled inherit the request, cancellation state is synchronized through the worker registry mutex, invalid/already-joined handles fail explicitly, main-thread observation remains false, unreachable cancellation support tree-shakes with the rest of the worker runtime, LSP completion/signature help expose both calls, and native regression coverage proves a parent cancellation reaches its running child before both are joined.
- [ ] Timers.
  - [x] Bootstrap blocking monotonic deadline timer with `time.sleepUntilMonotonic(deadlineMillis)`: the absolute `i64` deadline composes directly with `time.monotonicMillis()`, already-expired deadlines return immediately, native lowering rechecks the monotonic clock around EINTR-safe sleeps to avoid cumulative relative-sleep drift, LSP completion/signature help expose the contract, and unreachable timer support tree-shakes completely. Asynchronous task-integrated timers remain pending with the task/structured-concurrency model.
- [x] Bounded channel/message passing for the current Copy-scalar bootstrap: `channel.create(capacity) -> (i64, error)` creates a compiler-owned bounded FIFO, `channel.send(handle, value) -> error` and `channel.receive(handle) -> (i64, error)` transfer `i64` values with native blocking backpressure, and `channel.close(handle) -> error` wakes blocked operations and deterministically releases channel storage once in-flight operations leave. Capacity is bounded to `1..=65536`, invalid/closed handles fail explicitly, the pthread runtime tree-shakes when unreachable, and LSP completion/signature help expose the API. Richer payload types remain naturally sequenced behind their ownership/sendability rules rather than requiring source generics.
- [x] Worker/thread execution for the current capture-free bootstrap: `worker.start(work: fn() -> void) -> (i64, error)` launches compiler-owned work on a native pthread, `worker.startWith(work: fn(i64) -> void, argument: i64) -> (i64, error)` passes one Copy scalar argument without capture, and `worker.join(handle) -> error` waits exactly once through an opaque handle registry with explicit invalid/unknown/already-joined failures. The worker entry contract cannot capture outer locals, so borrowed application storage is not smuggled across the thread boundary; native pthread/runtime support tree-shakes when unreachable and LSP completion/signature help expose the API. Task results, structured concurrency, and broader sendability remain tracked by their dedicated concurrency items rather than being implied by this primitive; cooperative cancellation propagation is completed separately above.
- [ ] Data-race prevention integrated with ownership.
- [ ] Event-loop integration for UI targets.
- [ ] Server-oriented high-throughput I/O runtime.

# Milestone 9 — UI language and flat layout

The UI model must avoid Flutter-style deeply nested widget construction and object hierarchies. Sequencing note: the compiler-backed surface syntax is being prototyped early, before rendering backends, because the flat layout grammar is a core language constraint and should not be retrofitted after a widget-tree API takes shape.

- [x] `view` declarations/functions for the flat declarative UI model.
  - [x] Bootstrap top-level `view Name { ... }` declarations with visibility, source spans, formatter support, project merging, and semantic symbols.
  - [x] Parameterized `view Name(data: Type, optional: Type = default) { ... }` declarations: parameters are statically typed, defaults use the ordinary constant-default rules, view bodies can reference parameters, and parameter symbols retain editor spans/types.
  - [x] Additional view-producing function composition is intentionally omitted from the current language: parameterized views already compose as typed flat elements, while arbitrary view-returning functions would add builder-style construction without a demonstrated capability gap. Reopen only if a concrete use case cannot be expressed through typed data/view composition.
- [x] Views compose through typed data rather than subclassing: a declared Flux view can be used as another view's flat sibling element type, arguments are named properties checked against the target view's parameters/defaults, module visibility is enforced, and recursive composition cycles are rejected.
- [x] Flat element declarations.
  - [x] Bootstrap sibling element syntax (`Type name at row,column`) with unique local names and optional property expressions; nested child elements are syntactically rejected.
- [x] Grid-first layout.
  - [x] Bootstrap grid grammar with explicit columns/rows, logical fixed units, `fr` tracks, `auto`, gap, explicit padding, explicit row/column placement, and row/column spans lowers to the current native Linux/Android layouts. Common minimum sizing, margins/alignment, stable placement checks, and responsive property expressions are implemented; responsive track definitions, max/intrinsic sizing, and optional named areas remain explicit follow-up work.
  - [ ] Statically type/check element properties against built-in or interface-defined element contracts instead of treating property expressions as untyped view metadata.
    - [x] Bootstrap built-in element contracts validate known property names and property expression types, including typed function callbacks, without introducing widget classes; semantic symbols expose the property type for editor tooling.
    - [x] Declared Flux views act as custom element contracts derived directly from their typed parameters/defaults; custom-view property types flow into semantic/editor symbols.
    - [ ] Interface-defined platform/native element contracts after platform capability rules are mature.
  - [x] Validate placement against declared track counts and define overlap policy: row/column spans that escape the declared grid are static errors, and ordinary sibling grid regions may not overlap unless the grid explicitly opts into overlay composition.
  - [x] Named grid areas are intentionally omitted from the current grid language: stable element names plus explicit row/column/span placement keep the layout locally readable without introducing a second naming/indirection layer. Revisit only if real application layouts demonstrate a material readability win.
- [x] One-dimensional flex/flow layout where explicit grid coordinates are unnecessary: `flow: horizontal` / `flow: vertical` auto-place flat sibling elements in source order, support canonical `flow gap` / `flow padding` / `flow scroll` directives, reject manual placement/spans and mixed explicit grid tracks, format/LSP-highlight/complete as first-class Flux UI syntax, and lower on Linux/Android through compiler-synthesized native auto tracks with no wrapper object, widget hierarchy, or extra layout runtime.
- [x] Explicit overlay positioning when requested: flat grids accept `grid overlay: true`, allowing sibling row/column regions to overlap deliberately while preserving ordinary bounds validation, source-order native composition, and the no-wrapper flat layout model on Linux and Android. - [ ] Responsive breakpoints/container queries.

# Milestone 15 — Android target

Android is the first application-platform target. Android integration must feel like programming Android in Flux, not embedding a second Kotlin/Java application beside it: Flux code can directly use Android-specific modules for capabilities such as notifications, WorkManager/background work, vibration, intents, services, media, and sensors. The backend should prefer direct NDK/native APIs when Android provides them; for JVM/AndroidX-only framework APIs it generates the necessary Kotlin/Java bytecode/classes and JNI/native entry thunks automatically. No method-channel equivalent, hand-written JNI shim, serialized plugin call protocol, or user-maintained bridge package is required in ordinary Flux application code.
